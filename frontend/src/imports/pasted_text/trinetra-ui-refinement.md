Refine and improve the existing TRINETRA prototype UI.

IMPORTANT:
This is NOT a redesign from scratch.
Preserve the current product concept, information architecture, screens, and overall feature set.
Do NOT remove major functionality.
Do NOT oversimplify by deleting content.
The goal is to make the current prototype look cleaner, more organized, more elegant, and easier to understand.

TRINETRA is an AI-powered predictive cybercrime intelligence platform for law-enforcement agencies, financial institutions, and authorised investigation teams.

The current prototype already includes:
- Command Center
- Cases
- Prediction Engine
- Geo Intelligence
- Fraud Network
- OSINT Intelligence
- Alerts
- AI Copilot
- Reports
- Data Sources

The next refinement should focus on:
1. simplifying the visual density
2. making typography cleaner and less clustered
3. improving spacing and hierarchy
4. distinguishing SIH-required deliverables vs our added USP features
5. making maps more realistic and operational-looking
6. making the entire prototype easier to explain and present

===========================================================
OVERALL DESIGN GOAL
===========================================================

The refined design should feel:
- clean
- minimal but not empty
- premium
- well-spaced
- enterprise-grade
- trustworthy
- clear for judges and stakeholders
- polished enough for an investor / innovation / SIH presentation

The interface should still belong to the same visual family as the SutraAI CHI Agent:
- dark sidebar
- light main workspace
- teal for primary actions
- purple for AI / intelligence components
- calm white cards
- soft neutral greys
- limited and disciplined use of red/orange for risk

Do NOT make the UI flashy, futuristic, cyberpunk, or overloaded.
Do NOT use dense, tightly packed card layouts.
Do NOT use overly large blocks of text without hierarchy.
Do NOT make every section equally visually loud.

===========================================================
PRIMARY REFINEMENT OBJECTIVES
===========================================================

1. TYPOGRAPHY CLEANUP
The current interface feels visually clustered because of text density.
Refine the typography system so that it looks cleaner, calmer, and more readable.

Use a clear hierarchy:
- page title: strong, clean, prominent
- section title: smaller than page title but clearly distinguished
- card titles: concise and consistent
- labels: subtle and lightweight
- metadata: smaller and muted
- values / key metrics: bold and visually prioritized

Reduce visual noise by:
- increasing line spacing
- increasing spacing between headings and body text
- reducing unnecessary bold usage
- keeping descriptions shorter and crisper
- improving letter spacing slightly if needed
- keeping text alignment consistent

Use a modern, clean sans-serif such as Inter, Geist, or similar.
Overall feel should be more minimal and refined.

===========================================================
2. IMPROVE SPACING AND LAYOUT RHYTHM
===========================================================

Make the interface feel more breathable.

Increase:
- internal card padding
- spacing between sections
- spacing between charts/cards
- margins around main content
- spacing between label/value pairs

Use a more structured layout rhythm:
- clear section breaks
- consistent card heights where needed
- more balanced grid alignment
- visually calmer top sections
- avoid too many dense elements touching each other

The page should look intentionally composed, not packed.

===========================================================
3. CLEARLY DISTINGUISH “SIH REQUIRED DELIVERABLES” VS “OUR USP”
===========================================================

This is one of the most important refinement tasks.

Across the prototype, clearly show which features are:
A. CORE SIH DELIVERABLES
B. OUR ADDED USP / ENHANCEMENTS

Do this visually in a sophisticated and clean way.

Possible methods:
- section tags
- labels
- chips
- grouped information blocks
- dedicated summary cards
- legend system
- “Core Deliverables” vs “Added Intelligence Layer” labels

Use these distinctions especially on:
- Command Center
- Reports
- AI Copilot
- OSINT Intelligence
- Geo Intelligence
- Summary / Intro sections

Examples of SIH-required deliverables:
- predictive analytics engine
- likely withdrawal location prediction
- GIS hotspot mapping
- law-enforcement interface
- alert generation
- case management
- model-based intelligence for intervention

Examples of OUR USP additions:
- OSINT Evidence & Credibility Layer
- misinformation / truth verification across news, public web, and signals
- explainable AI reasoning layer
- Fraud Graph Intelligence
- AI Copilot / chatbot interface
- enhanced evidence-backed decision assistance

Create one or more clean summary components where this difference is immediately understandable.

For example:
- “SIH Required Deliverables” card
- “TRINETRA USP Additions” card

These should be highly readable and presentation-friendly.

4. REALISTIC MAP REFINEMENT
===========================================================

The current maps are good but still too schematic.
Refine all map-based screens to look more realistic and operational.

Make the map design feel closer to real GIS / intelligence systems.

Use:
- more realistic India / regional map outlines
- clearer geographic boundaries
- subtle administrative context
- more realistic city placement
- more realistic hotspot markers
- better geographic texture
- actual district/city naming
- clearer legend and scale relationships

Do NOT make maps overly stylized or cartoon-like.
Do NOT make them look like abstract infographic maps.

The Geo Intelligence and Command Center maps should feel like:
“a real operational risk map used by cybercrime analysts.”

Possible realism additions:
- map tiles or simplified GIS basemap style
- district or zone boundaries
- ATM cluster markers
- state boundaries
- subtle road/urban zone references if zoomed in
- real city labels
- clear map legend
- realistic tooltip / popup panels

When showing hotspot detail, make it feel grounded:
- real place names
- plausible linked case counts
- realistic probability and zone labels
- clear explanation of why this area is risky
